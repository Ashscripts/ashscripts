Lesson 6.5: Windows App Deployment: Win32 and Beyond: Ashpak packages and deploys every Windows application at scale :

The Scene Wednesday morning. Microsoft 365 apps are deploying. iOS and Android are covered. Ashpak turns to the hardest part: Windows application deployment. The audit spreadsheet has a dedicated tab for Windows apps. He scrolls through:

This is the core challenge of Windows app management: the real world runs on traditional .exe and .msi installers; not on modern packaged apps. Intune's Win32 app type is the solution.

Win32 App Deployment: How It Works

The Win32 Content Prep Tool Every Win32 app must be wrapped using Microsoft's free IntuneWinAppUtil.exe tool:

Packaging 7-Zip:

1 CMD (as administrator): 2 C:\IntunePackaging\IntuneWinAppUtil.exe 3 -c C:\IntunePackaging\Source\7-zip\ 4 -s 7z2301-x64.msi 5 -o C:\IntunePackaging\Output\ 6 7 OUTPUT: 8 Creating intunewin package... 9 File 7z2301-x64.intunewin created 10 Size: 1.87 MB (compressed)

Building the 7-Zip Win32 App in Intune

Detection Rules; Critical Detection rules tell Intune how to know if the app is already installed. If the detection rule doesn't match, Intune keeps trying to install:

7-Zip detection rule:

1 Rule type: MSI 2 MSI product code: {23170F69-40C1-2702- 3 2301-000000000000} 4 MSI product version check: Not configured 5 (any version counts)

Assignments:

1 Required: INTUNE-DEV-WINDOWS-CORPORATE 2 INTUNE-DEV-WINDOWS-BYOD 3 (All enrolled Windows devices; 4 7-Zip is standard utility) 5 → Create

Packaging Chrome (EXE installer) EXE installers are slightly more complex: no MSI GUID available:

Program tab for Chrome:

1 Install command: 2 ChromeSetup.exe /silent /install 3 4 Uninstall command: 5 "C:\Program Files\Google\Chrome\Application\ 6 {version}\Installer\setup.exe" 7 --uninstall --system-level --force-uninstall 8 9 Install behavior: System

Detection rule for Chrome (File-based):

1 Rule type: File 2 Path: C:\Program Files\Google\Chrome\Application 3 File or folder: chrome.exe 4 Detection method: File or folder exists

Dependencies; Installing Prerequisites First Some apps require prerequisites. AutoCAD needs Microsoft Visual C++ and .NET Runtime. Intune handles this with dependencies:

19 1. Checks if Visual C++ installed 20 → Not installed → installs first 21 2. Checks if .NET 8 installed 22 → Not installed → installs next 23 3. Both dependencies ready → installs AutoCAD

Supersedence: Replacing Old Versions When AshScript moves from Adobe Reader DC to Adobe Acrobat 2024:

1 SUPERSEDENCE CONFIGURATION: 2 intune.microsoft.com 3 └── Apps → Adobe Acrobat 2024 4 └── Supersedence tab 5 → + Add supersedence 6 App: Adobe Reader DC 7 Uninstall previous version: 8 Yes 9 (Intune uninstalls Reader DC 10 THEN installs Acrobat 2024) 11 12 RESULT: 13 Devices with Adobe Reader DC: 14 → Reader DC uninstalled automatically 15 → Acrobat 2024 installed automatically 16 → No manual IT intervention needed 17 18 Devices without any Adobe app: 19 → Only Acrobat 2024 installs 20 → No supersedence action triggered

Microsoft Store Apps (New); WinGet Integration For apps available in the Microsoft Store, Intune now uses the new Microsoft Store integration (WinGet-based); much simpler than Win32 packaging:

1 intune.microsoft.com 2 └── Apps → + Add 3 App type: Microsoft Store app (new) 4 → Search: "VLC media player" 5 → VLC media player

6 → Select 7 8 NAME: VLC Media Player 9 SOURCE: Microsoft Store (winget) 10 11 ASSIGNMENTS: 12 Available: INTUNE-DEV-WINDOWS-CORPORATE 13 (optional; user installs from 14 Company Portal)

Microsoft Store app (new) vs Win32: The new Store app type uses WinGet under the hood; Windows' built-in package manager. It: Handles download, installation, and updates automatically No packaging required; no IntuneWinAppUtil needed Automatically keeps apps updated via WinGet Limited to apps in the Microsoft Store catalogue For apps not in the Store, Win32 is still required.

Win32 App Deployment Monitoring

1 intune.microsoft.com 2 └── Apps → Monitor → App install status 3 4 Filter: Platform = Windows, Type = Win32 5 6 APP INSTALLED PENDING FAILED 7 7-Zip 23.01 798 2 0 8 Google Chrome 795 4 1 9 Adobe Acrobat 790 6 4 ← investigate 10 AutoCAD 2024 23 2 0 11 (Design team: 25 devices) 12 13 CHROME FAILURE; INVESTIGATE: 14 Device: ASHPC-DESIGN-08 15 Error: 0x87D1041C (detection rule mismatch) 16 → Detection rule: chrome.exe in 17 C:\Program Files\Google\Chrome\Application 18 → But Chrome installed in: 19 C:\Program Files (x86)\Google\ (32-bit) 20 Fix: Update detection rule to check 21 both paths OR use registry detection

Troubleshooting Win32 App Issues

Issue 1: App Shows Failed with 0x87D1041C

1 SYMPTOM: Win32 app shows Failed 2 Error: 0x87D1041C 3 4 MEANING: App detection rule not matched 5 after install attempt 6 (Intune installed it but can't 7 detect it as installed) 8 9 MOST COMMON CAUSE: 10 Detection rule looking for wrong path 11 or registry key 12 13 DIAGNOSIS: 14 On device: Check if app actually installed 15 Open Programs and Features: 16 Is 7-Zip listed? → App installed OK 17 Detection rule is wrong 18 19 Run detection script manually:

20 PowerShell: Test-Path "C:\Program Files\ 21 7-Zip\7z.exe" 22 Returns: True / False 23 24 FIX: 25 Update detection rule: 26 Apps → 7-Zip → Edit → Detection rules 27 → Correct the path/registry key 28 → Save → Device re-evaluates

Issue 2: Silent Install Fails (Application Needs UI)

1 SYMPTOM: App fails with error during install 2 Works fine when installed manually 3 4 CAUSE: Installer requires user interaction 5 (licence agreement, custom path etc.) 6 /quiet or /silent flag not working 7 8 DIAGNOSIS: 9 Run install command manually in admin CMD: 10 "ChromeSetup.exe /silent /install" 11 Does it install without prompts? /× 12 13 If it shows UI: Installer doesn't support 14 silent mode with that flag 15 16 FIX: 17 Find correct silent install parameters: 18 Vendor documentation 19 IEAK (for Chrome) 20 MSI transform files 21 silentinstallhq.com (community resource) 22 23 Example Chrome enterprise MSI (better): 24 msiexec.exe /i googlechromestandalone 25 enterprise64.msi /qn /norestart

Issue 3: App Reinstalls After User Uninstalls It

1 SYMPTOM: User uninstalls an app 2 Next Intune sync reinstalls it

3 User is frustrated 4 5 CAUSE: App is assigned as Required 6 Required = persistent enforcement 7 8 DIAGNOSIS: 9 Is this expected behaviour? 10 If app is REQUIRED → YES, this is correct 11 Required apps should not be removable 12 13 DECISION: 14 If app should be optional: 15 Change assignment from Required → Available 16 User gets choice in Company Portal 17 18 If app must stay: 19 Inform user that this is a required 20 corporate app and cannot be removed 21 from managed corporate devices

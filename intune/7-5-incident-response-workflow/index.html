The Scene

Lesson 7.5: Incident Response Workflow: Ashpak builds the playbook AshScript will follow for every future incident :

The Scene Friday afternoon. Phase 7 is nearly complete. Ashpak has investigated two real incidents this week; ransomware and credential theft. He handled both well. But he got lucky in one respect: he was in the office. What happens at 3 AM when he's asleep and a new incident fires? He opens a document and starts writing. Not a Intune profile. Not a KQL query. A playbook; the documented, repeatable process for handling security incidents at AshScript.

23 → No investigation needed; known bad

Blocking the malicious domain:

Key Concepts to Lock In: Phase 7

Concept Remember This

MDE vs Windows Defender Defender = AV only; MDE = EDR + hunting + response + vuln mgmt

MDE sensor = "Sense" Windows service; streams continuous telemetry

Device isolation Cuts all network except MDE: investigation continues

Live Response Remote shell into device; collect, remediate, investigate

Concept Remember This

Advanced Hunting KQL on 30-day telemetry; proactive threat hunting

Automated investigation MDE AI investigates alert + remediates automatically

ASR prevalence rule Blocks new/rare executables from internet; stops 0-days

MDE risk → Intune Risk score shared via connector → drives compliance state

High risk = non-compliant Automatic CA block when active threat detected

IoC indicators Block known-bad file hashes/domains across entire fleet

Custom detections KQL rules that run on schedule; org-specific threat logic

Incident playbook Detect → Contain → Investigate → Remediate → Recover → Review

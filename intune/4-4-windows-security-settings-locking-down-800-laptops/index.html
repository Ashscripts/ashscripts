The Scene

Thursday morning. 9:17 AM. A Microsoft Security Advisory notification appears in Ashpak's inbox: MSRC Advisory CVE-2024-XXXX; CriticalActive exploitation detected. Windows SMBv1 protocol is being leveraged in ransomware attacks targeting enterprise networks. Organisations with SMBv1 enabled are at immediate risk. Mitigation: Disable SMBv1 on all Windows endpoints immediately. Ashpak opens Intune's device inventory. He runs a quick filter. 340 laptops. Spread across Mumbai, Pune, Bangalore. Some in the office. Many at home. Some on client sites. In the old world; before Intune; this would have required: A helpdesk ticket for each device Remote sessions with each user Physical visits for offline devices 3-5 days of work minimum Ashpak looks at the clock: 9:19 AM. He opens the Settings Catalog. Creates a new profile. Adds one setting: Disable SMBv1. Assigns it to all Windows devices. Saves. By 9:31 AM; 12 minutes later; the profile is deploying to all 340 affected devices. By the next check- in cycle, SMBv1 is disabled fleet-wide. He replies to the security advisory email:

"Remediated. 340 devices. Done." 1 Filter: Windows devices with SMBv1 enabled 2 Result: 340 devices

This is the power of Windows security configuration in Intune.

Windows Security Configuration: The Landscape

Intune offers multiple overlapping tools for Windows security configuration. Understanding which tool to use for which purpose is critical:

Ashpak's approach: Start with Security Baselines for the foundation, add Settings Catalog

profiles for specific requirements, and use Endpoint Security profiles for focused security workloads. This gives layered, comprehensive coverage.

Layer 1: Security Baselines

Security Baselines are pre-built collections of settings that Microsoft recommends for security hardening. They represent the collective knowledge of Microsoft's security team, the NSA, CIS benchmarks, and real-world threat intelligence.

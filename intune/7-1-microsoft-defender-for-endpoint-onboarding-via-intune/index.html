The Scene

The Scene Monday morning. Phase 7. Ashpak arrives to find an email from the security team timestamped 2:47 AM:

SUBJECT: Suspicious Activity; ASHPC-FINANCE-03 "Automated alert from Windows Defender: Suspicious PowerShell execution detected on ASHPC- FINANCE-03. Process attempted to reach external IP 185.220.101.x (known Tor exit node). Alert auto-resolved by Windows Defender. No further action taken by system." "No further action taken by system."

Ashpak reads that last line again. A Finance laptop reached out to a Tor exit node at 2 AM. Windows Defender flagged it. And then... nothing. No investigation. No isolation. No understanding of what the PowerShell script was trying to do. No check of whether other devices were affected. No timeline of events. Windows Defender is reactive. It quarantines files. It blocks processes. But it doesn't investigate. It doesn't correlate. It doesn't hunt. Microsoft Defender for Endpoint (MDE) does all of that; and more. He opens the Microsoft Defender portal: security.microsoft.com .

"847 devices. Zero are onboarded to MDE. That changes today."

AshScript's M365 E3 licences include Microsoft Defender for Business; a version of MDE scaled for organisations under 300 users. For AshScript's 847 devices, they need MDE Plan 1 or Plan 2 (included in M365 E5 or as a standalone add-on). Ashpak confirms with procurement: AshScript has M365 E5 → MDE Plan 2 included.

MDE Architecture: How It Works

Connecting MDE to Intune Before onboarding devices, Ashpak must connect the MDE tenant to Intune. This enables: Onboarding devices via Intune (no manual package deployment) Compliance integration (MDE risk score → Intune compliance) Conditional Access based on device risk

Onboarding Windows Devices via Intune With the connection established, Ashpak creates an onboarding configuration profile that deploys the MDE sensor to all Windows devices:

1 intune.microsoft.com 2 └── Endpoint Security 3 └── Endpoint Detection and Response 4 └── + Create Policy 5 Platform: Windows 10 and later 6 Profile: Endpoint detection 7 and response 8 → Create 9 10 Name: WIN-MDE-Onboarding-All 11 Description: Onboards all AshScript Windows 12 devices to Microsoft Defender 13 for Endpoint (MDE) 14 Deploys MDE sensor silently

What happens when this profile deploys? The MDE sensor is silently installed on every Windows device. The sensor starts streaming telemetry to the MDE cloud. Within 24 hours, all 800 Windows devices appear in the MDE device inventory at security.microsoft.com . No user interaction. No restarts required.

Warning: macOS system extension + TCC required: Remember Lesson 4.5? Ashpak already approved com.microsoft.wdav.epsext (Defender system extension) and granted Full Disk Access via TCC policy. Verifying on a Windows device:

1 On device: PowerShell (admin) 2 Get-Service -Name Sense 3 Status: Running 4 StartType: Automatic 5 6 (The "Sense" service is the MDE sensor) 7 8 OR: Check Security Centre 9 Windows Security → Device Security 10 → Core isolation: On 11 → Defender for Endpoint: Connected 12 → Sensor ID shown (unique per device)

MDE Security Settings Management Once devices are onboarded, Ashpak can manage Defender settings directly from the MDE portal; without Intune configuration profiles. This is called Security Settings Management:

1 security.microsoft.com 2 └── Settings → Endpoints 3 └── Configuration management 4 → Endpoint security policies 5 6 Creates policies that deploy directly 7 via MDE (not via Intune MDM channel): 8 → Antivirus settings 9 → Attack surface reduction 10 → Firewall settings 11 12 ADVANTAGE: 13 Works even for devices not fully enrolled 14 in Intune MDM (e.g. Linux devices, 15 non-compliant devices still get AV settings) 16 17 ASHPAK'S NOTE: 18 For enrolled devices: use Intune profiles 19 (already configured in Phase 4) 20 Security Settings Management: 21 used for edge cases and non-MDM devices

Investigating the 2 AM Alert; Now With MDE Now that ASHPC-FINANCE-03 is onboarded to MDE, Ashpak investigates the 2 AM alert properly:

1 security.microsoft.com 2 └── Incidents & alerts → Alerts 3 → Search: ASHPC-FINANCE-03 4 5 ALERT: Suspicious PowerShell execution 6 Severity: Medium 7 Status: New 8 Device: ASHPC-FINANCE-03 9 User: finance.user@ashscript.com 10 Time: 02:14:33 11 12 → Click alert → View full investigation 13

Device Timeline: 30-Day Forensic Record MDE records everything. Ashpak opens the device timeline:

This investigation took Ashpak 4 minutes. Without MDE, it would have taken hours of manual log analysis; if the logs even existed. The 30-day device timeline stores every process creation, network connection, file operation, and registry change. This is the power of EDR.

Taking Action; Isolating the Device The device may still be compromised; the scheduled task is still there, update.bat is still there. Ashpak isolates the device while he investigates:

1 security.microsoft.com

2 └── Assets → Devices 3 → ASHPC-FINANCE-03 4 → Device actions 5 → Isolate device 6 7 ISOLATION: 8 Device is cut off from ALL network traffic 9 EXCEPT the MDE sensor connection 10 (Ashpak can still investigate remotely) 11 User loses all network access 12 13 NOTIFICATION TO USER: 14 Sent automatically: 15 "Your device has been isolated by IT 16 security. Please contact the IT helpdesk 17 immediately. Do not power off your device."

Collecting the malicious files:

1 security.microsoft.com 2 └── ASHPC-FINANCE-03 3 → Device actions 4 → Collect investigation package 5 6 Downloads: ZIP containing 7 → Process memory dumps 8 → Network connections at time of alert 9 → Scheduled tasks list 10 → Registry autorun keys 11 → Prefetch files (recently executed) 12 → Event logs 13 14 Ashpak opens the package: 15 Scheduled task XML: confirms malicious task 16 update.bat: confirmed dropper script 17 No evidence of lateral movement 18 No evidence of data exfiltration

Remediation:

1 security.microsoft.com 2 └── ASHPC-FINANCE-03 3 → Device actions 4 → Run antivirus scan 5 → Initiate automated investigation

6 7 AUTOMATED INVESTIGATION RESULT (45 mins): 8 Malicious scheduled task: Removed 9 update.bat: Quarantined 10 Registry entries: Cleaned 11 No lateral movement detected 12 13 → Release device from isolation: 14 Device actions → Release from isolation 15 16 TOTAL INCIDENT TIME: 2 hours 17 (Detection → Investigation → Remediation)

1 HIGH: Ransomware-linked behaviour detected 2 Device: ASHPC-SALES-19 3 User: sales19@ashscript.com 4 Time: Yesterday 23:41 5 Detail: Rapid file encryption pattern detected 6 in Documents folder. 847 files renamed 7 with .crypted extension in 4 minutes.

Alert 2:

1 HIGH: Credential dumping attempt 2 Device: ASHPC-DEV-07 3 User: dev07@ashscript.com 4 Time: Today 08:12 5 Detail: Process attempted to read LSASS memory. 6 Process: suspicious_tool.exe 7 Blocked by Credential Guard

Two high-severity threats. On real employee devices. Right now. Ashpak takes a breath. He was going to spend today configuring automated response policies. Instead, he's going to do both; investigate these threats AND configure automation so future threats handle themselves.
